          Hva dette viser

          • Skybasert uten servere: GeoParquet og PMTiles leses direkte fra objektlagring. Ingen PostGIS eller GeoServer å drifte.
          • Analytikeren beskriver, Claude Code utfører: spørsmål på norsk blir til SQL, skript, kart og rapport.
          • Etterprøvbart: skriptene ligger i repoet (ai-demo/scripts/) og kan kjøres på nytt for neste Overture-utgave.
          • Datakvalitet blir synlig: kildesporing per objekt, sikkerhetsscore på steder og hvor stor andel som har høyde.

          Begrensning: Overture er et åpent, globalt datasett. Kategorier og høyder kan mangle eller være feil, og bør kontrolleres mot autoritative kilder før beslutninger.

          Fra demo til 100 interne brukere

          Samme oppskrift, uten egen KI-infrastruktur

          Appen trenger ingen server og ingen API-nøkkel. Hver bruker logger inn med sin egen Claude-konto, og bruken belastes den kontoen. Det som må på plass for 100 brukere er lisenser, datadeling og felles arbeidsmåter, ikke drift.

          Brukerflate

          • Artifacts deles innad i organisasjonen med lenke og tilgangsnivå.
          • KI-spørsmål går på hver brukers egen Claude-plass. Ingen nøkler i koden.
          • Delte funn lagres i appens egen database og er synlige for kollegene.

          Data

          • GeoParquet og PMTiles i egen bøtte, oppdatert av en planlagt jobb.
          • Samme filer brukes av kart, DuckDB, QGIS og GeoLibre.
          • Sensitive data blir i egne systemer og nås via MCP-koblinger med brukerens tilgang.

          Analytikere

          • Ett repo med CLAUDE.md (koordinatsystem, datakilder, navngiving).
          • Egne skills, for eksempel «Overture-uttrekk», «bydelsanalyse» og «publiser kart», distribuert som plugin.
          • Claude Code på web eller i terminal, med styrt nettverkstilgang.

          Styring

          • Enterprise gir blant annet SSO, brukerstyring og administrasjon av tilganger.
          • Anthropic trener ikke modeller på data fra kommersielle planer som standard.
          • Retningslinjer for hvilke data som kan brukes med KI, og menneskelig kontroll av resultater.

          En realistisk innføringsplan

          5 personer · 4 uker

          Pilot

          • To GIS-analytikere og tre fagbrukere.
          • Lag repo, CLAUDE.md og to–tre skills for vanlige analyser.
          • Én delt KI-kartapp på egne data.
          • Mål tidsbruk før og etter på 3–5 reelle oppgaver.
          25 personer · 2–3 måneder

          Utvidelse

          • Egen bøtte med GeoParquet og PMTiles og nattlig oppdatering.
          • MCP-kobling til internt kartgrensesnitt eller database.
          • Opplæring: «å spørre godt», kildekritikk og kontroll av tall.
          100 personer · løpende

          Drift

          • Skills og maler som plugin i organisasjonens katalog.
          • Et lite fagmiljø som eier datagrunnlag og maler.
          • Jevnlig gjennomgang av bruk, kostnad og kvalitet.

          Når trengs Claude API i stedet?

          Når løsningen skal brukes av folk uten Claude-konto, for eksempel innbyggere på en åpen nettside, eller kjøre automatisk uten en innlogget bruker. Da kalles Claude fra en liten tjeneste som holder nøkkelen, med bruksgrenser. Kartverktøyene i denne appen kan gjenbrukes nesten uendret.

          Dette kan dere vise kolleger i dag

          • Spør i kartet og se Claude bruke verktøy, tegne diagram og flytte kartet.
          • Del et funn og åpne det fra en kollegas maskin.
          • Vis analysesiden og skriptene i repoet: alt er etterprøvbart.
          • Be Claude Code lage samme analyse for en annen by. Det tar minutter.

          Funksjoner, planer og vilkår endrer seg. Sjekk gjeldende informasjon fra Anthropic før innkjøp.
